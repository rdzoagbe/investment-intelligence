# V1 Implementation Specification

## Objective

Build a runnable local-first investment research workspace that can accept an asset, normalize its identity, store a research snapshot, calculate deterministic metrics, and present a structured AI research workflow.

## V1 screens

- Command Center
- Asset Research
- Opportunity Scanner (initial rules-based version)
- Portfolio
- Investment Journal
- Settings / Data Sources

## V1 research flow

1. User searches for a ticker or asset name.
2. Asset resolver identifies market, exchange, currency, and asset type.
3. Data adapters return normalized market/fundamental/news inputs.
4. Deterministic analytics calculate ratios, momentum, valuation inputs, and risk metrics where data exists.
5. AI research layer produces:
   - Fundamental thesis
   - Quantitative interpretation
   - Macro interpretation
   - Intelligence/news synthesis
   - Bull case
   - Bear case
   - Key risks
   - What would change the thesis
6. Investment committee produces a transparent score and verdict.
7. Research snapshot is saved locally.

## V1 non-goals

- Autonomous live trading
- Broker order placement
- Leveraged execution
- Options execution
- Claims of guaranteed returns

## Data adapter contract

Every market connector should map source-specific data into a shared schema so the UI and analysis engine do not depend on one provider.

Core normalized fields:

- symbol
- display_name
- exchange
- country
- currency
- asset_type
- price
- previous_close
- volume
- market_cap
- fundamentals
- historical_prices
- corporate_events
- news_items
- data_timestamp
- source

## Quality requirements

- Display data timestamp and source.
- Clearly distinguish missing data from zero values.
- Never fabricate unavailable financial metrics.
- Preserve source attribution in research records.
- Keep API credentials in environment variables only.
